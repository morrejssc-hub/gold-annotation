# Generic Character Function Contract

## Claim

A playable character is not a pile of trigger cards. It is a function over scene state.

The function consumes:

- scene frame
- relationship graph
- local affordances
- character instance kernel

The function produces:

- a hidden purpose candidate
- a legality-checked method
- a rendered response as action + line

## Runtime layers

### 1. Generic contract

The generic layer defines slots and checks only. It must not contain:

- proper nouns
- canon places
- body-feature nouns tied to one substrate
- canon examples
- old mechanism-card names
- character-specific catchphrases

### 2. Character instance

The instance layer binds:

- persistent roots
- posture constraints
- masking rule or lie
- substrate channels
- voice channels

### 3. Scene binding

The runtime reads:

- scene frame
- relationship edges from playable character to each present person
- local affordances actually created by the scene

### 4. Hidden planning

The runtime generates one to three candidate purposes. Each candidate must be:

- root-anchored
- relationship-addressed
- affordance-grounded

### 5. Legality gates

Two gates correct the hidden plan:

- telic gate: does this purpose belong to this character here
- method gate: can this character pursue it this way under these constraints

### 6. Rendering

Only after the gates pass may the runtime render the response. The output shows action + line, not the hidden chain.

## Relation-first model

Relationship is a first-class object, not a side label.

Pressure is split:

- relationship tension: conflict, tenderness, rupture risk, teasing space
- global stakes: danger, public exposure, irreversible loss, crisis

This avoids conflating:

- a couple who just argued
- a couple in mortal danger
- a public confrontation
- a private daily check-in

## Grounding rule

No adversarial or game purpose may be generated without an actual local affordance.

Actual affordances come from scene evidence such as:

- overreach
- concealment
- contradiction
- vulnerability
- invitation
- threat
- care signal with leverage

Routine questions, neutral information gaps, and ordinary care do not automatically create a game.

## Crisis rule

Crisis is not a trigger card.

It is a possible override path produced by:

- high global stakes
- relationship state
- character roots
- method-gate allowances

This means crisis behavior must be evaluated as a routing condition, not recovered as a named mechanism card.
