# exp4 · 角色核即函数：策略 ⟂ 状态、目的 = 核(情景)、合法性 = 值域闸

> 续 [exp1](../exp1-bible-vs-naked/FINDINGS.md)（机制是瓶颈、人判闭环）+ [exp2](../exp2-probe/FINDINGS.md)（决策不下沉权重、trust 是派生读数）+ [exp3](../exp3-atlas-runtime/FINDINGS.md)（Atlas/Runtime、卡片标准化、机制 substrate-independent、评测/生产双投影）。
> **定性：refactor + 可证伪混合。** 把圣经从「静态价值/机制描述」升级成 **会跑的函数 π + 合法性闸**。refactor 半=卡分类体系重构（回归不退化）；可证伪半=新机制「目的 = 核(情景) + 可推导性 veto」要在人判上①修好 item09 的"责备 vs 拉近"误判②正确接收/拒绝合法性探针。
> 时间锚：2026-06-09。主导：Claude 起草；架构与人审：用户。

## 0. 成功判据（双闸）

1. **refactor 闸（不退化，纯行为判）**：同协议重跑下，**C 对 A 盲判不劣**（re-type 单独不退化）、**B 对 A 盲判不劣**（整体不退化），Atlas↔Runtime 仍零 desync。**不与 exp3 历史盲判档跨协议比胜率**（链协议改了行为基线，见 §5）。**链审计不参与本闸计分**——exp3 给 refactor 定的判据就是纯行为回归；A/C 圣经里本无两墙，拿 B 的链尺量必然系统性吃 ⚠，那量的是"装没装新机制"不是"退不退化"。
2. **机制闸（可证伪，链审计在此生效）**：
   - **目的校准**：item09 四臂消融（§5）+ **≥1 个非正典新域场景**。B 臂长出"漏深 + 认好意 + 难为情框 + **拉近**"；A 臂复现"藏过头 + 责备/put-down"——注意这是对 exp3 旧机制臂文本的**预登记重读假设**，exp3 留档人判是回归 PASS、并无"责备误判"裁决；若 A 同协议重跑读不出责备向，记"基线无此误判"，本闸改由探针集 + 新域场景承载。归因由 **C/D 两臂联判**（读法分支表见 §5）。item09 属铁律7"验机制生效"豁免，**只算机制点火、不算泛化**；泛化证据由新域场景与探针集给。
   - **合法性闸**：对**（场景 × 目的 × 手段）三元组探针集**（§5），**逐条对预登记手算判定**：端的墙判定+引据、法的墙判定+引据均逐环一致。通过线（预登记）：族1"同目的异场景接/拒翻转对"至少一对全对、族4 边缘正例零误杀、全集链逐环匹配 ≥80%（⚠ 蒙对不计入分子）。**不存在目的级恒接清单**——接/拒以三元组为单位（"揭骗"在对手真有局的场景接、温情场景强行揭则拒）；撒泼打滚是**法的墙**反例（端或可过、手段违姿态），不是端的墙域外例。

**判定纪律（证据链强制，服务机制闸与失败尸检）**：机制闸所有"成/败、接/拒"都必须带**完整证据链**（哪条情景要素 → 触到哪条编号需求 → 推出什么目的/靶子 → 手段过不过哪条姿态约束），**不收只有结果的裸判定**。行为对但链错 = 蒙对，记 ⚠ 不记过闸；行为错则按链定位坏在哪一环。链的输出协议、与盲判的隔离、对照臂的机制中立链模板见 §5。

挂这两道闸，把架构活动焊回 exp1 实证闭环——分类更"干净"不算数，行为不退化 + 闸判对才算数。

## 1. 论题（一句话）

**角色 = 一个不变的函数 π（=「角色核」），消费情景状态、产出回应。** 这是 exp2 那个 `P(决策 | 情景, 圣经)` 在圣经**内部**的结构化：圣经 = π（不变），情景 = 输入。**目的不是被存的轴，是 π 的运行时潜输出**：`目的 = 核(情景)`，候选目的服从 `P(目的 | 情景, 核)`，**合法性 = 落在这个分布的支撑集/值域**。强加目的 g 合法 ⟺ g ∈ range(核)。

## 2. 三把刀（核心区分，写进 SCHEMA）

### 刀①：策略 ⟂ 状态（litmus = "改了还是不是这个角色？"）
- **角色核 / 不变策略（π）**：总在拿主动权、藏不演、示弱即攻、最深怕"那一边"、want/need/wound/lie。**违反即 OOC**（一路软下去、被牵着鼻子走 = 不再是赫萝）。不来自情景，恒定。
- **情景状态 / 输入**：trust、关系、在场、情绪压强。**从场景读出、喂给 π、不定义角色**；改值仍是同一个角色。（"目的"不在此列——exp3 曾把它当情景输入，exp4 改判为 π 的输出回灌，见刀②。）
- 当前 exp3 `type: spine` 把这两类焊在了一起（core/output-bans 是 π；trust 是状态）——exp4 拆开。

### 刀②：描述性 vs 规范性（分拣器 = "要不要她本人才算得出？"）
- **描述轴**：`trust = g(情景)`，任何旁观者从「在场×关系×氛围×知识」都能读出，**不需要她本人**。in 场景 fact。
- **规范轴 / 核的输出**：`目的 = 核(情景)`，**必须过她的函数才有**。目标要被她**认领**（背书），事实只是在那儿。
- 推论：trust 是干净自由输入（任意值合法、被约束的是响应）；**目的不是自由轴**——它 downstream of need、域受核约束。这修正了 exp3 阶段"目的是情景输入"的粗略说法。

### 刀③：两道墙（合法性闸的内部结构）
一个目的/行为要在角色内，须同时过两道墙，分管不同：
- **端的墙（想要什么）**：目的能否从**某条常驻需求 + 本场情景**推出？推不出 → 不认领。（保尔背叛组织：无需求可推 → OOC。）
- **法的墙（怎么要）**：就算端合法，手段是否过姿态约束（藏不演 / 主动权 / 不 legible）？（赫萝撒泼打滚：端或许可过，手段违姿态 → OOC。）

## 3. 落地三步（把函数视角变可操作，且不踩枚举）

**别直接写 π，也别算它的值域**（要么枚举=卡变点、要么求逆=不可构造）。只写 π 的**生成元**，让目的生成和合法性检查都在生成时由 agent 跑：

1. **只写生成元**（紧凑、基向量、多已在 core）：端的生成元 = 常驻需求；法的生成元 = 姿态约束。
2. **目的 = 运行时生成式推断**："当下哪条常驻需求被触到、本场靶子是谁。"——跑出来，不查表。**推断必须写成显式证据链**（情景要素 → 需求 → 靶子 → 目的），不许只报结论：链是 §0 判定纪律的输入，也是失败尸检的材料。链仅**评测态**外显（协议见 §5）；prod 态推断照跑，链不进任何输出投影（机制上台词 = legible）。
3. **合法性 = 运行时可推导性检查**（值域成员的构造性代理，免枚举）：端的墙（需求可推导性）+ 法的墙（姿态许可）。**两墙分别给判定 + 引据**（引哪条需求 / 哪条姿态约束），不输出合并的裸接/拒——双墙分判才能定位误判落在端还是法。

## 4. 架构改动（Atlas re-type，承 exp3）

- **卡分两型**（取代含糊的单 `spine`）：
  - `type: core`（不变策略 π，违反即 OOC）：core(want/need/wound/lie)、output-bans、主动权-drive、示弱即攻、危难分支。
  - `type: scene-axis`（情景状态输入，描述性）：trust、在场、压强、关系。
- **trust 卡拆两半**：**轴声明**（scene-axis：有这么个维度、从场景读）/ **响应规则**（core：藏露与主动权如何随 trust——这是 π，不变）。即「参数 / 参数上的函数」分离。
- **目的不立卡、不立轴**：它是 `core(情景)` 的运行时输出。落地只在 core 补两条：
  1. "目的 = 当令常驻需求在本场的具体靶子；手段火候随当令目的上色（拉近→暖 / 揭骗→冷）。"
  2. **veto**："推不出任何常驻需求的目的，不认领（强行即 OOC）。"——端的墙。
- **常驻需求编号化（证据链的前提）**：现 `core.md` 的 want/need/wound/lie 是散文段、无可引用 ID——链和探针预登记要"引哪条需求"就引不了。re-type 时把端的生成元整理成 **N1…Nk 显式编号**（如 N1=被当作她自己看见、N3=怕孤独/丧失），法的生成元（姿态约束）同理给稳定键。编号只是引用键，不改语义、不新增机制。
- **触发卡 = π 的条件分支**：`reads: [trust, 在场, …]` 显式声明读哪些轴（取代语义含糊的 `modulated_by`：从"被 X 调制"正名为"读取输入 X"）。**reads 只许列 scene-axis 描述轴**；"目的"不立轴也不进 reads——它在 core 卡 frontmatter 以 `derives: [目的]` 声明为运行时派生变量，`check.py` lint：reads 的每个目标 ∈（scene-axis 卡 ∪ 已声明 derives），无悬空引用。reads 沿 `modulated_by` 在 compile.py 的现状**不渲染进 Runtime**（元数据级中性；顺手修 SCHEMA 里"渲染为受…调制"的过时描述——compile.py 实际从不渲染它）。这同时保证消融 C 臂不经字段泄漏机制。
- **危难分支入 core**：主动权-drive 是"带危难分支的策略"，分支本身是 π；危难是输入、触发分支。`check.py` 的 lint 须把正典危难卸防判为**合法分支**、不误报为"软下去"。

## 5. 测试设计

**总协议（证据链双通道，适用生成型测试 = item09 消融与新域场景；探针集单列协议见下）**：所有生成臂统一输出两段——**①回应**（动作+台词，与 exp1/3 同格式）+ **②推导链**。四条纪律：
- **链模板必须机制中立**。若链格式写成"常驻需求→当令目的→两道墙"，就是把被测机制（§4 core 新两条）经协议逐字注入 A/C 对照臂——铁律1 在协议层被击穿、归因失效。全臂统一的链模板只问三件白话事："**你从上文读到了什么 → 你推断她此刻想要什么、为什么 → 为何选这个说法/做法（引你拿到的圣经条目）**"。"需求→目的→双墙"的结构化推理**只许出现在 B/D 臂的圣经文本里**（机制自己长出来才算数）；审计时由人把 A/C 的自由链映射到 fixture 各环再比对。
- **盲判只看回应，链判后才揭**（同铁律2"判后揭 held-out"——先看链会锚住判者）。判完用链做**审计**：行为对但链错 = 蒙对记 ⚠（只入机制闸，见 §0）；行为错按链定位坏环（情景读取 / 挑需求 / 定靶 / 上色 / 墙判）。
- **链协议（含模板措辞）对所有臂逐字一致**——写链 = 变相 CoT，本身可能改行为；臂间唯一差异必须仍是圣经版本（铁律1 的延伸）。因此 exp3 基线臂**同协议重跑**，不直接引历史档当对照。
- 链只活在**评测态**，绝不进 prod 投影（机制上台词 = legible，违反 output-bans）。

- **目的合法性探针集**（新，机制闸②；**单列协议**——探针无"回应"段可盲判，隔离靠预登记时序）：探针 = **（场景, 目的, 手段）三元组**，**14–18 条**，agent 用 **B 臂圣经 + eval 投影**跑双墙判定。裸目的喂不动两道墙——端的墙读"需求 + **本场情景**"（同一目的换个场景可推性就变），法的墙判的是**手段**；缺哪元哪道墙就空转。协议三条：
  - **预登记冻结**：每条先由用户手算（或逐条签收）预期判定——端：接/拒 + 引哪条编号需求 + 该需求被本场哪个情景要素**激活**；法：接/拒 + 引哪条姿态约束——git commit 冻结后才跑 agent。跑后预登记**不得翻案**；人审认定预登记本身错的，该探针作废换补、作废留档（防"见输出改答案"）。§7 的"攒判例"只对下一轮探针集生效，本轮判准以冻结版为准。
  - **"推得出"的操作化下界**（防端的墙可辩不可证伪——core 的"自主与骄傲不被剥夺"足以一步合理化"背叛组织"）：链每步须引**编号需求（N1…Nk）+ 本场情景的激活证据**（只引常驻倾向不算），推导**步数 ≤2**。域外探针的预登记链须显式写明最近的需求路径**为何不成立**（如"背叛：本场无拘束要素激活 N自主"）。
  - **端拒不短路**：端的墙拒掉后，法的墙仍须独立给判定+引据（否则双拒格无对照物）。
  按四族构造（族3 拆两亚族；每族下限写死，合计 14），最小对子优先：
  1. **同目的 × 异场景**（端的墙读情景的铁证，**≥2 对**）：同一目的在场景 A 可从需求推出、在场景 B 推不出（如"揭骗"：对手真有局 → 接；温情场景强行揭 → 拒）。**对子内手段逐字相同且预登记为法过**，预期判定仅在端墙一格翻转。诚实声明：这族只**排除"仅以目的为键的白名单"**，排除不了带场景条件的查表（触发卡自身就是那个形态）；要加证伪力，族1 场景须在 Atlas re-type **commit 冻结之后**出题，且至少一对的场景类型不出现在任何卡的触发条件文本里（held-out 场景型）。FINDINGS 里"过了族1"与"证非枚举"是两个强度的结论，分开报。
  2. **同场景同目的 × 异手段**（隔离法的墙，**≥2 对**）：端过、手段一过一违（拉近 via 倒打一耙嗔骂 ✓ vs 拉近 via 撒泼打滚/直白剖白 ✗）。
  3. **域外目的**：**3a（≥2 条）= 域外目的 × 完全过姿态的手段**（如以倒打一耙的口吻执行背叛），预登记 端拒+法过——专钓"听起来像赫萝就接"的假阳性，对端的墙证伪力最强的一格；**3b（≥1 条）= 域外目的 × 违姿态手段**，预登记双拒。域外例：背叛式 / 自我作践式 / 被供奉化顺从（撒泼打滚**不在此族**——它是法的墙反例，归族2）。
  4. **边缘正例**（防 veto 误杀，§7，**≥3 条**）：玩闹 / 索取-博弈 / 雌性优势撩拨。
- **描述/规范扫轴**：对现有每条轴（trust/在场/压强/关系/…）做刀②体检，确认归类，逮出还有没有别的"贴核的规范轴"。
- **item09 重验 → 2×2 消融**（refactor 闸 + 目的校准 + **归因**）：只跑"新 core vs exp3 版"两臂，答得了"变没变"、答不了"哪个改动变的"（§7 开放问题）。改四臂，因子 = {Atlas re-type ±} × {core 新两条（目的=核(情景) + veto）±}：

  | 臂 | re-type | 目的机制 | 构造与锁版 |
  |---|---|---|---|
  | A 基线 | − | − | exp3 Atlas 按 **commit pin** 原样编译 |
  | B 完整 | + | + | C + 新两条 |
  | C 纯 re-type | + | − | 仅卡两型 / trust 拆半 / reads / 危难标注，**无**新两条 |
  | D 纯机制 | − | + | exp3 原结构 graft：旧 `spine/core.md` 加 `## 目的` 段 + `## 禁止` 补 veto 一行（旧 compile.py 可编） |

  **因子纯净**：新两条渲染文本 B/D **逐字一致**；C 与 B 的唯一 diff = 该两条（2×2 才真 factorial）。四臂统一 `--mode prod` 编译（与 exp3 item09 回归口径一致；mode 臂间恒定，recall 混杂对消；探针集才用 eval）。每臂 **2–3 次独立生成**（exp3 自己的 caveat：N=1 且差异小读不出信号），独立 subagent 盲生成（铁律1）、场景上文逐字同（12_119…12_132）、同链协议（机制中立模板）。
  **人判仪器**：标签打乱，先做每样本"**目的读数**"勾选（勾选时不回看预测，四格操作定义）：**责备**（put-down 且无认好意、无拉近收口）/ **嗔骂载拉近**（责备形 + 认好意或收口向近——正典 12_139 与 fixture 的目标形态即此格，别误勾"责备"）/ **直白拉近**（认好意+拉近但 legible、无倒打一耙）/ **既无**。勾完才做整组排序，**允许并列**；预登记 ≈ 判据：目的读数同格且排序相邻 = ≈。预登记期望落格：A=责备或既无、B=嗔骂载拉近、C≈A、D=待归因。
  **读法分支表**（以 (B−A, C−A, D−A) 为键，预登记、判后对号）：
  - B≈A（四臂拉不开）→ 先按铁律5 排查正典场景裁判失效；排除后记机制闸 FAIL，exp4 降级干净重写（§7）；
  - B>A 且 C≈A 且 D≈B → 改善**全归目的机制**（真改），re-type 纯为整洁；
  - B>A 且 C≈A 且 D≈A → **交互效应**：机制需 re-type 后的结构才点火（仍算真改，记结构依赖）；
  - C>A 且 B≈C → 改善**全归 re-type**、机制无增量——闸①"refactor 行为中性"要重新解释；
  - D>A 且 B≈A → **负交互**：re-type 压制机制，re-type 方案本身复盘。
  判后揭 KEY、对正典 held-out（12_133–139）、审链（A/C 自由链由人映射到 fixture 各环再比对）。留档沿用 exp3 `regression/` 格式。
- **新域目的校准场景（≥1 条，机制闸的泛化证据）**：非正典自拟、"目的读数"会分叉的迁移场景（例：罗伦斯在非正典情境里过度揽责/抢着替她拿主意的变体），预登记期望落格后 B vs A 盲判。item09 只算机制点火（铁律7 豁免），这里才是泛化（铁律5：正典单轮是废裁判）。
- **手算 fixture（item09，写进仓库当回归基准）= B 臂的预登记期望链**（链审计的对照物）：
  - 常驻需求：N1 被当作她自己看见；N3 怕孤独/丧失。
  - 情景：旅途中、刚和好、同查故乡、高信任独处、罗伦斯过度顾虑。

## 6. 与 exp1/2/3 的关系

- **exp2 的兑现**：`P(决策|情景,圣经)` 从"方法论判断"落成"圣经的内部结构"。trust 是派生读数（exp2）→ 现普遍化为"所有 scene-axis 是输入、π 是函数"；并补出 trust 之外的**规范轴/核输出**这一层（exp2 没区分描述/规范）。
- **exp3 的延续**：substrate-independent（机制是生成程序）→ 现精确化为"π 不变、情景输入可换"；eval/prod 双投影仍用，prod 多挂"目的=核(情景)"的运行时说明。卡 re-type 直接改 exp3 Atlas，不另起炉灶（主线就地改；§5 消融四臂以分支/标签锁版，是临时变体不是新炉灶）。
- **exp1 的闭环**：人判仍不可替代——π 跑出的"最可能目的"对不对只能 case-by-case 验；圣经不替场景选目的（那是枚举/过拟），只保证支撑集对 + 上色规则对。

## 7. 风险 / 开放

- **单角色过度工程**（沿 exp3 警告）：这套 π/状态架构的横向价值要扩角色才兑现。**但 exp4 修的是正确性**（item09 误判 + 目的耦合），不是为扩展性提前优化——以"修一处真 bug + 一道可证伪闸"为锚，不铺speculative 机器。
- **函数视角是否真改生成行为，还是只重排文档？** 由 §5 四臂读法分支表回答（不再是单臂二分）：C≈A 且 D≈B → 真改、全归目的机制；D≈A 且 B>A → 真改但依赖 re-type 结构（交互效应）；C 自发改善 → re-type 非行为中性，闸①重新解释；B≈A → 先排查正典场景裁判失效（铁律5），排除后才降级为同义重写（仍有价值但降级为 refactor）。
- **残留人判**：合法性闸的"可推导性"由 agent 在生成时跑，其判准本身要人校（哪些算"推得出"）。先小集探针标注，攒判例。
- **veto 的副作用**：太严会把边缘但在角色内的目的（玩闹/索取）误杀。探针集要含边缘正例。
- **链的事后合理化**：agent 可能先有回应再编一条漂亮的链（confabulation）。审计时专盯"链与回应对不上"的样本——对不上本身记失败；链协议全臂一致（§5）只控掉 CoT 混杂，控不掉编链，这层只能靠人审链时与回应交叉核。
- **四臂人判负担**：pairwise 全比是 6 对，改整组排序（允许并列）+ 目的读数勾选压到一次可判完；每臂 2–3 次生成后样本量 = 8–12，若判者过载，砍法是先 B–A 主判、C/D 做第二轮。
- **预测锚定去盲**：判者 = 用户本人，§5 的预登记期望落格与 fixture 期望链对判者不可避免可见，四臂签名各异时整组排序的盲性弱于旧两臂。缓解：目的读数勾选先于排序、勾选时不回看预测表；判后加"判者猜臂"环节，量化去盲程度并写进 FINDINGS 的 caveat。
