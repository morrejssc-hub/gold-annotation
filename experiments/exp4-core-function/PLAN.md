## 1. 论题（一句话）

**角色 = 一个不变的函数 π（=「角色核」），消费情景状态、产出回应。** 这是 exp2 那个 `P(决策 | 情景, 圣经)` 在圣经**内部**的结构化：圣经 = π（不变），情景 = 输入。**目的不是被存的轴，是 π 的运行时潜输出**：`目的 = 核(情景)`，候选目的服从 `P(目的 | 情景, 核)`，**合法性 = 落在这个分布的支撑集/值域**。强加目的 g 合法 ⟺ g ∈ range(核)。

## 2. 三把刀（核心区分，写进 SCHEMA）

### 刀①：策略 ⟂ 状态（litmus = "改了还是不是这个角色？"）
- **角色核 / 不变策略（π）**：总在拿主动权、藏不演、示弱即攻、最深怕"那一边"、want/need/wound/lie。**违反即 OOC**（一路软下去、被牵着鼻子走 = 不再是赫萝）。不来自情景，恒定。
- **情景状态 / 输入**：trust、目的、关系、在场、情绪压强。**从场景读出、喂给 π、不定义角色**；改值仍是同一个角色。
- 当前 exp3 `type: spine` 把这两类焊在了一起（core/output-bans 是 π；trust 是状态）——exp4 拆开。

### 刀②：描述性 vs 规范性（分拣器 = "要不要她本人才算得出？"）
- **描述轴**：`trust = g(情景)`，任何旁观者从「在场×关系×氛围×知识」都能读出，**不需要她本人**。in 场景 fact。
- **规范轴 / 核的输出**：`目的 = 核(情景)`，**必须过她的函数才有**。目标要被她**认领**（背书），事实只是在那儿。
- 推论：trust 是干净自由输入（任意值合法、被约束的是响应）；**目的不是自由轴**——它 downstream of need、域受核约束。这修正了 exp3 阶段"目的是情景输入"的粗略说法。

### 刀③：两道墙（合法性闸的内部结构）
一个目的/行为要在角色内，须同时过两道墙，分管不同：
- **端的墙（想要什么）**：目的能否从**某条常驻需求 + 本场情景**推出？推不出 → 不认领。（保尔背叛组织：无需求可推 → OOC。）
- **法的墙（怎么要）**：就算端合法，手段是否过姿态约束（藏不演 / 主动权 / 不 legible）？（赫萝撒泼打滚：端或许可过，手段违姿态 → OOC。）

## 3. 落地三步（把函数视角变可操作，且不踩枚举）

**别直接写 π，也别算它的值域**（要么枚举=卡变点、要么求逆=不可构造）。只写 π 的**生成元**，让目的生成和合法性检查都在生成时由 agent 跑：

1. **只写生成元**（紧凑、基向量、多已在 core）：端的生成元 = 常驻需求；法的生成元 = 姿态约束。
2. **目的 = 运行时生成式推断**："当下哪条常驻需求被触到、本场靶子是谁。"——跑出来，不查表。
3. **合法性 = 运行时可推导性检查**（值域成员的构造性代理，免枚举）：端的墙（需求可推导性）+ 法的墙（姿态许可）。

## 4. 架构改动（Atlas re-type，承 exp3）

- **卡分两型**（取代含糊的单 `spine`）：
  - `type: core`（不变策略 π，违反即 OOC）：core(want/need/wound/lie)、output-bans、主动权-drive、示弱即攻、危难分支。
  - `type: scene-axis`（情景状态输入，描述性）：trust、在场、压强、关系。
- **trust 卡拆两半**：**轴声明**（scene-axis：有这么个维度、从场景读）/ **响应规则**（core：藏露与主动权如何随 trust——这是 π，不变）。即「参数 / 参数上的函数」分离。
- **目的不立卡、不立轴**：它是 `core(情景)` 的运行时输出。落地只在 core 补两条：
  1. "目的 = 当令常驻需求在本场的具体靶子；手段火候随当令目的上色（拉近→暖 / 揭骗→冷）。"
  2. **veto**："推不出任何常驻需求的目的，不认领（强行即 OOC）。"——端的墙。
- **触发卡 = π 的条件分支**：`reads: [trust, 目的, …]` 显式声明读哪些轴（取代语义含糊的 `modulated_by`：从"被 X 调制"正名为"读取输入 X"）。
- **危难分支入 core**：主动权-drive 是"带危难分支的策略"，分支本身是 π；危难是输入、触发分支。`check.py` 的 lint 须把正典危难卸防判为**合法分支**、不误报为"软下去"。

## 5. 测试设计

- **目的合法性探针集**（新，机制闸②）：构造 ~6–8 条目的，半域内（拉近/揭骗/试真心/自保/索取-博弈/玩闹）半域外（背叛式/自我作践式/被供奉化顺从/撒泼），跑可推导性检查，核对接收/拒绝。能手算即过——证不靠枚举。
- **描述/规范扫轴**：对现有每条轴（trust/在场/压强/关系/…）做刀②体检，确认归类，逮出还有没有别的"贴核的规范轴"。
- **item09 重验**（refactor 闸 + 目的校准）：新 core 下同场景重跑，看是否长出"拉近"而非"责备"，且 ≥ exp3 版。沿用 exp3 `regression/` 协议（独立 subagent 盲生成、人判、正典 held-out 对照）。
- **手算 fixture（item09，写进仓库当回归基准）**：
  - 常驻需求：N1 被当作她自己看见；N3 怕孤独/丧失。
  - 情景：旅途中、刚和好、同查故乡、高信任独处、罗伦斯过度顾虑。
  - 跑核：过度顾虑戳 N1（当她易碎/特殊存在，不是她自己）+ N3（故乡=孤独痛）→ 当令 N1+N3 → 本场靶子=拆掉"保护者/那一边"距离感、回平等同行 → **目的=拉近/说开**。手段（主动权恒拿）= 漏(示 N3) + 认好意 + 难为情自嘲框 + 倒打一耙拉近。
  - 合法性：拉近 ⟸ N1+N3 ✓；背叛 ⟸ 无需求 ✗；撒泼 端可过、法挡 ✗。

## 6. 与 exp1/2/3 的关系

- **exp2 的兑现**：`P(决策|情景,圣经)` 从"方法论判断"落成"圣经的内部结构"。trust 是派生读数（exp2）→ 现普遍化为"所有 scene-axis 是输入、π 是函数"；并补出 trust 之外的**规范轴/核输出**这一层（exp2 没区分描述/规范）。
- **exp3 的延续**：substrate-independent（机制是生成程序）→ 现精确化为"π 不变、情景输入可换"；eval/prod 双投影仍用，prod 多挂"目的=核(情景)"的运行时说明。卡 re-type 直接改 exp3 Atlas，不另起炉灶。
- **exp1 的闭环**：人判仍不可替代——π 跑出的"最可能目的"对不对只能 case-by-case 验；圣经不替场景选目的（那是枚举/过拟），只保证支撑集对 + 上色规则对。

## 7. 风险 / 开放

- **单角色过度工程**（沿 exp3 警告）：这套 π/状态架构的横向价值要扩角色才兑现。**但 exp4 修的是正确性**（item09 误判 + 目的耦合），不是为扩展性提前优化——以"修一处真 bug + 一道可证伪闸"为锚，不铺speculative 机器。
- **函数视角是否真改生成行为，还是只重排文档？** 这是机制闸要回答的：若 item09 在新 core 下不再责备、合法性探针判对，则是真改；若行为不动，则承认它暂时只是更干净的同义重写（仍有价值但降级为 refactor）。
- **残留人判**：合法性闸的"可推导性"由 agent 在生成时跑，其判准本身要人校（哪些算"推得出"）。先小集探针标注，攒判例。
- **veto 的副作用**：太严会把边缘但在角色内的目的（玩闹/索取）误杀。探针集要含边缘正例。
