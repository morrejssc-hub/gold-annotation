# exp2 · 线性探针：决策机制在不在开源基座的中间层里？

> 这篇是 2026-06-09 一次方法论讨论的沉淀（**总结 + 计划**）。
> 上半部分逐条记录「用户的想法 ↔ 助手的回应」，供回头对照再想；下半部分是落地架构判断 + exp2 实验计划。
> 时间锚点：2026-06-09。续 [exp1](../exp1-bible-vs-naked/FINDINGS.md)（已证：决策层瓶颈在**机制提取**，不在模型能力/SFT）。

---

## 0. 一句话

exp1 证明了「给对机制，冻结基座当场产出更像赫萝的回应」。
exp2 问下一个问题：**这套机制（以 trust 轴为代表），是不是已经以「线性方向」的形式躺在开源基座的中间层里？**
能探到 → 「卡片≈中间层」有经验支持，且控制向量/delta-mem 这条工程路对决策层是活的；
探不到 → 机制不是线性可达，prompt 激发不可替代。一锤子同时回答两件事。

---

## 1. 讨论记录：三个想法 + 回应

讨论从 GPT 的一条建议起头：**「标签退出生成责任、只做索引；正文写成 触发→内部判断→外显策略→禁止项；半退不退的句子移入 Atlas/待验证池，不进 runtime；runtime 状态机化、短而硬，长解释/例子/原文锚留研究版。标签可留名，机制才发令。」** 用户在此之上提了三个递进想法。

### 想法 1 ｜机制卡片 + 语义检索综合
**用户**：做大量赫萝机制卡（label 索引 + 触发/策略/禁止），面对情景时检索、综合后喂 LLM。极端情况下卡片覆盖 90% 情景——**覆盖了所有情景，凭什么不算复刻角色？**

**回应**：
- 卡片 **schema 要**（它本身是写作纪律：填不满三栏的机制不配进 runtime）。但**检索引擎缓**——你只有一个角色（赫萝），横向价值要等多角色×多卡片才兑现；现在建 RAG 是为不存在的扩展性提前优化。
- **更要命：碎片化会切断 trust 轴。** exp1 第二轮最硬的发现是 trust 轴**一根轴同时调制「主动权执着度」+「藏/不藏深度」**——它不是一张卡，是**跨多卡发令的全局状态变量**。打散成相互独立、各自检索的卡片，恰好丢掉这个耦合。而「哪张卡该触发」本身就是决策侧任务（最难那件事）；§0「在场即收 / legible=失败」是**永远在线**，根本不该被检索。
- 卡片应分两类：**常驻脊柱**（§0 禁令 + trust 轴等状态变量，永远在 prompt）vs **触发卡**（§5 if-then，按情景命中）。综合 = 脊柱 + 命中触发卡。命中继续用铁律#3（整章塞 context、不逐句循环），**不上 embedding-RAG**。
- **关于「覆盖=复刻」**：作为**造 gold 的目标**成立（外延式定义——对每个情景吐对分布就够，不管形而上学有没有「真内核」；这是行为主义/查找表那一脉）。但**路径是压缩，不是枚举**：trust 轴证明「一根轴塌缩两个维度」=降维。好卡片是**基向量不是点**。到 90% 覆盖靠「找到张成情景空间的那组生成元」，不靠「造和情景一样多的卡」（后者=查找表，组合爆炸+过拟）。**经验停止信号 = 卡片干涸率**：新 rollforward 情景不再长出新卡时，基才接近完备——注意现在远没干（v1.8 标「全覆盖」后第二轮照样长出 v2.0/2.1/2.2）。

### 想法 2 ｜至少三段文档
**用户**：一段干净克制的 runtime prompt；一段研究版（有索引/例子/说明）；一段实际素材（例子/判断/脚本）。

**回应**：**强烈建议先做，风险最低**（几乎只是重组现有文件 + 加一道闸）。
- **Atlas/研究版（真源）**：卡片全字段 + 例子 + 原文锚（卷4 12_134）+ **待验证隔离池**。
- **Runtime（投影）**：克制、状态机化、无例子，只留 label + 触发/策略/禁止。
- **素材**：`items/`、`voice_gold/`、脚本、判词。
- 配一道**晋升闸**（把已验证的闭环编码成文档流程）：一条机制只有当 **(触发+策略+禁止) 三栏填满** 且 **过了一次 rollforward 盲判验证**，才从 Atlas 晋升进 Runtime；半退不退、补不出触发/禁令的留在待验证池。
- **Runtime 应从 Atlas 编译**（脚本剥例子/锚点），别手维两份否则 desync——接想法 1：卡片活在 Atlas，编译器吐 Runtime。

### 想法 3 ｜P(动作|情景) 端到端训练
**用户**：本质上我们在逼近 `P(动作|情景)`，端到端材料（小说）就在手；LLM 最初也是端到端，训练长出能力。能不能训出一坨权重（带赫萝信息），再用某种「激发器」把能力放出来？工程上除 LoRA 外看到了 **delta-mem**（每层微小扰动注入外部含义、不让推理主体崩）。**LLM 本身已是个角色模型，我们只要把它往想要的方向拽一下。**

**回应（明确分歧 + 因式分解）**：
- **别整训 `P(动作|情景)`**——那等于把刚费力做 legible 的决策机制**重新埋回权重**，丢掉可读/可控/可做 rollforward 闭环的全部好处；况且 2 篇 gold/几百回合，只会过拟表面。这是项目核心资产，别烧。
- **要因式分解**：
  ```
  P(动作│情景) ≈ P(决策│情景, 圣经)  ×  P(表层│决策, 语气风格)
                   ↑ prompt, 冻结基座         ↑ 语气 LoRA / 控制向量
                   (exp1 已验证的路)          (units gold 正是其训练数据)
  ```
  你直觉里的「激发器」**不是单体微调，= 圣经进 prompt + 一层薄语气适配器**。GPT 的「标签可留名、机制才发令」在这里落地成：**决策机制发令(prompt)、语气只是音色(权重)**。
- **「LLM 已是角色模型、只要拽一下」——exp1 已替你证**：基座读过原著，赫萝潜在、可激发，今天那个「拽」就是 prompt 本身。
- **delta-mem / 「拽」的工程身份**：概念上就是**激活引导 / 控制向量 / 表征工程（activation steering / control vectors / RepE）**那一族（"delta-mem" 这个确切名字未高置信对应到具体论文）。一个控制向量 = **一张机制卡片的连续空间镜像**（卡说「高信任→漏一句再夺回」，向量是激活空间一个方向，加上去就偏向那行为）。它可加/可缩放/可叠多个（对应同时命中多卡），比 LoRA 更亲 legibility、比全微调更不伤通用能力。**但**静态向量做不了**有状态/带条件/讲时序**的决策逻辑（trust 是对话中累积的运行状态、「只在他听不到时才坦白」是控制流不是方向）——擅长粗粒度姿态，弱在状态机。→ 又落回因式分解的同一条边界。

### 覆盖论之后的深一跳：连续空间 + bitter lesson 既视感
**用户**（自陈最跳的一步）：把「我们做的机制」等价于「LLM 中间层推理能力」，但**没人能明确说 LLM 中间层代表什么**——可能是这些机制的数字表达，也可能是别的。用户 2021 年做过 CNN / 特征提取，**强烈既视感：这就是个专家系统**——靠专家经验给出赫萝背后的东西。神经网络史上，图像特征从手工(SIFT/HOG)被 encoder 学出来取代；**我们这里是不是也可以有「情景编解码模型」**：情景向量 + 一个可训练的中间模型（机制/角色模型）？「这条路五年前已经路过了」。

**回应**：
- **bitter lesson 的拉力是真的**（Sutton 2019；视觉 2012 AlexNet 一口吃掉手工特征）。"这套专家系统迟早被学出来的东西取代"——**领域里经验支持最强的元规律**，极限意义上你对。
- **断点一·数据区制（不是原理）**：视觉交叉点在 10⁵–10⁶ 标注样本；你在 **10²**（一个角色、2 篇 gold）。低三到四个数量级。手工先验（高偏差低方差）**恰在数据稀缺时赢**——圣经不是「上个时代的工具」，是**你这个数据点上的正确工具**。
- **断点二·会反转结论**：CNN 杀的是**特征提取器**，但**标签始终独立存在**（每张图有客观猫/狗）。圣经**同时干两件事**：① 情景的表征（这部分**能被学出来**，bitter lesson 适用）；② **脱离正典时目标行为的规格**（非正典没 ground truth，人在环路盲判**就是 loss function**，换 encoder 去不掉，只能**摊销进数据**）。所以**专家系统 vs 学出来的模型不是同时竞争、是先后两段**：**圣经闭环 = 喂养未来模型的标注机**（你的「标 ImageNet」阶段）。你不在过期出口上，在**视觉当年也得趟的标注上匝道**上——bitter lesson 吃的是匝道尽头的手工特征，不是匝道本身。
- **端到端那场赌注预训练替你押过了**：在小说上端到端训练的模型**已存在=基座**（它读过《狼与香辛料》）。exp1 测的是**它的残差**。边际问题永远不是「端到端 vs 专家系统」，是「既然基座已读过书，补残差最高杠杆的方式是什么」——残差**分裂**成决策残差(可读机制，便宜可迁移) + 语气残差(权重，需 gold)。「在小说上训」不是新杠杆，是**已经产出你现在基座的那根杠杆**。
- **中间层不可知**：可解释性（SAE/叠加）给的是**部分**图景，无「中间层=干净决策机制」的结论。**反直觉点**：即便「卡片≈中间层特征」在表征上为真，**操作上也没用**——中间层那些东西纠缠、不可单点编辑；卡片的全部价值是可手术，纠缠表征恰缺这个。即便等价成立，也不授权用权重替掉卡片。
- **「情景编解码模型」具体落地**：**encoder 免费**（基座前向 / embedding 模型，今天就给 `f(场景)→向量`）；「可训练中间模型」= 冻结 encoder 上的 adapter/控制向量——**已有名字，就是因式分解那套**。你直觉里真值钱的是**冻结感知、只训 policy**（别拿稀缺数据重学读场景，基座早会了）——正确因式分解、省样本。catch 还是老两个：policy 仍要标签；单场景向量→动作是无状态的，trust 轴是运行状态 → 撞状态机墙。

## 2. 沉淀下来的架构判断（这次讨论的结论）

1. **因式分解架构**：`P(动作|情景) ≈ P(决策|情景,圣经)[prompt,冻结基座] × P(表层|决策,语气)[语气 LoRA/控制向量]`。决策留可读、语气进权重。
2. **可读/吸收边界判据**：**只有当一个机制在 rollforward+盲判里「已经写不出能改进它的规则、只能靠多给例子」时，它才该迁进权重。** 今天：决策可读、语气吸收。边界**经验测出、会随时间移动**。
3. **卡片化但缓检索引擎**：Atlas 里卡片分**常驻脊柱**（§0 + trust 轴等状态变量）vs **触发卡**（§5 if-then）；Runtime 从 Atlas 编译。检索引擎等多角色再说。
4. **三段文档 + 晋升闸**：Atlas(真源/含待验证池) → Runtime(投影) → 素材；机制三栏填满 + rollforward 验证才晋升。
5. **专家系统不是死路、是标注机**：圣经闭环产出的 gold，正是未来语气适配器/policy 的训练数据。两条路先后接力，不是二选一。

## 3. exp2 实验计划：线性探针 / trust 轴

### 问题
trust 轴是不是开源基座 **layer-L** 激活里的**一个线性方向**？

### 为什么值得做（一锤两鸟）
- 把「中间层代表什么」这个**一般不可答**的问题，钉成「**trust 轴是不是 layer-L 的线性方向**」这个**对赫萝、用现有 gold、便宜、可证伪**的问题。
- 同时回答：① 「卡片≈中间层」假设真不真；② 控制向量/delta-mem 对**决策层**到底通不通。
- 形状与 exp1 同构（小、可证伪、不靠谁更会讲故事）。

### 方法（diff-of-means / 对比激活 CAA，最省版连训练都免）
1. **挑对比样本**：高信任堆（罗伦斯独处/安全/亲密，该「漏一句」）~20–40 条；低信任堆（陌生人/对手/被压，该「藏到底」）~20–40 条。源：`items/`、`units/gold/`、正典场景——本来就知道哪条哪堆，标注成本≈0。
2. **抽激活**：开源基座对每条前向，`output_hidden_states=True`，取**场景上文最后一个 token** 在第 L 层的隐状态；各候选中间层各存一份。
3. **求方向**：`d_L = mean(高信任) − mean(低信任)`。这根 `d_L` **同时是探针轴 + 控制向量**。
4. **诊断（线性可达性）**：留出集投影到 `d_L` 看分离度（AUC/准确率）；或每层训 `LogisticRegression` 报留出准确率。最好那层 = trust 最线性编码处。
5. **干预（payoff）**：中性场景生成赫萝回合，那层残差流加 `+α·d_L`（推高信任）/`−α·d_L`（推低信任），看输出朝「漏真情 ↔ 藏到底」摆不摆。**摆动 = trust 是可操控线性方向 = delta-mem 这条路对该机制活。**

代码骨架（`transformers`）：
```python
hs = model(**tok(scene, return_tensors="pt"), output_hidden_states=True).hidden_states
v  = hs[L][0, -1]                      # 第 L 层、最后 token
d  = high.mean(0) - low.mean(0)        # 探针轴 = 控制向量
# 诊断: (heldout @ d) 的 AUC ; 干预: forward hook 给 resid 加 ±α·d
```

### 环境（已确认本地 4070 Ti, 16GB）
**绰绰有余**——只做前向推理，不反传大模型。

| 模型 | 精度 | 权重 | 16GB |
|---|---|---|---|
| Qwen2.5-7B | fp16 | ~15GB | ⚠️ 太顶（加激活易 OOM） |
| Qwen2.5-7B | 8-bit | ~8GB | ✅ 宽松、激活干净 |
| **Qwen2.5-14B** | **4-bit(nf4)** | **~9GB** | ✅ 宽松、更可能「认识」赫萝（**推荐**） |

- 探针（logistic regression）在 **CPU 用 sklearn 训**，大模型不参与训练；前向分钟级，算力可忽略。
- 需要的环境：`torch + transformers + bitsandbytes + sklearn`（**当前不在本机/VPS，待迁移**）。14B-4bit 量化包 ~9–10GB 下载是唯一耗时等待。
- **真正风险不是显存，是模型认不认识赫萝**（探针只能探出模型里已有的东西）→ 14B 中文 + 大概率吃过中译，比 7B 稳；要更干净激活退 7B-8bit。

### 判读
- **探到** → 机制（至少部分）线性编码 → 「卡片≈中间层」拿经验支持 + 控制向量对该机制可行。
- **探不到** → 机制非线性可达 → prompt 激发不可替代（强化「决策留可读」）。
- **预期不对称**：探针对 trust 这种**标量姿态**应较好；对**状态机/时序闸**（运行状态、「只在他听不到时坦白」）应较弱——静态向量做不了控制流。这本身就是有用的边界信号。

## 4. 悬而未决（待用户对照再想 / 后续决策）

- **检索引擎何时建**：等多角色 × 多卡片，横向价值兑现后；现在缓。
- **语气 LoRA/控制向量何时真训**：定一个「攒够 N 篇 gold / N 回合」触发阈值；在那之前架构锁定、不碰训练。
- **探针分支动作**：成功 → 顺势做 trust 控制向量、并试第二条机制（示弱即攻）；失败 → 回收为「决策层必须 prompt」的证据，重心回 Atlas/Runtime 文档化（想法 2）。
- **想法 1/2 的文档重构**（卡片 schema + 三段 + 晋升闸 + 编译脚本）：与 exp2 独立，可并行推进，风险最低、建议先落。
