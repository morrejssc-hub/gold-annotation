# anchors · 锚点记录

这里放逐场正典锚点日记。它们是机制工作的入口，不是机制结论。

## 生成流程

逐卷锚点按以下五步走，结论由人定稿：

1. **双模型分别生成。** Claude 与 GPT-5.5 两臂各自独立产出，不共享中间结果——保住两个真模型的异质对比。不得用 subagent 顶替任一真模型臂（同源会制造“已交叉验证”的假象）。
2. **一步生成，不预选范围。** 每臂通读整卷（经 `canon/tools/canon_slice.py` 切片），在一步内完成“选范围 + 精读 + 写锚点”：主轴 scene 详写，物流／过场一句带过。范围切分本身是要被对比的判断，不提前抹平。
   - 退化条款：仅当某卷长到一步通读不可靠（中段开始漏情节）时，才加一个**客观分幕目录**（只列 scene 摘要，不做“算不算关系锚”的判断）；两臂仍各自一步精读。
3. **显式锚点（范围留痕）。** 锚点开头显式标注主轴 scene／只读梗概段／为什么这么切，并能回指 `canon/maintext/卷NN.json`。范围决策是一等输出，不进黑箱，方便对比时第一刀就并排比两臂的范围切法。
4. **分别对比。** 从新 session 交叉对比两版：先比范围切法，再比同范围处的精读。对比只机械列差异（事实／范围／读法三类分歧），不自评谁优。
5. **人审定稿。** 必须由人拍板的部分：① 裁决并存读法、决定主稿吸收什么、怎么合；② 读法升格为机制候选的判断；③ 准入测试与字段增删的 gate（见 `架构笔记.md` §0，防 intimacy／conflict residue 那类回潮）；④ 机制正文／policy 定稿；⑤ 原文口径冲突时的最终采信。

分界线：事实层与差异呈现可自动化；裁决、升格、准入、定稿必须人来——凡“需要品味或拍板”的地方都归人。

## 文件要求

- 文件名尽量含卷、scene 范围和短标题，例如 `锚_卷02_s25-28_烂好人.md`。
- 必须能回指 `canon/maintext/卷NN.json` 的 scene 范围。
- 允许记录疑问、并存读法和弱模式；不允许把单锚直接写成 Policy。
- 若引用原文，保持短摘；主要写观察和解释路径。

## 弱约束

当前不加字段化 frontmatter。每则锚点只需满足：

- 能回指正典范围。
- 分清事实观察、暂时读法、暂存弱模式。
- 暂存弱模式必须标明临时、带条件、非定稿。
- 不要求产出机制候选。

## 目录布局

- `extract/claude/`、`extract/codex/`：两个真模型臂各自的原始锚点（Claude 臂走 Claude Code subagent；Codex / GPT-5.5 臂是外部真模型）。两臂独立、不共享中间结果。
- `notebook/`：跨臂对比/合并后的产物。卷01–03 是这套双臂流程之前的早期合并稿，留作对照。
