# anchors · 锚点记录

这里放逐场正典锚点日记。它们是机制工作的入口，不是机制结论。

## 生成流程

逐卷锚点按以下五步走，结论由人定稿：

1. **双模型分别生成。** Claude 与 GPT-5.5 两臂各自独立产出，不共享中间结果——保住两个真模型的异质对比。不得用 subagent 顶替任一真模型臂（同源会制造“已交叉验证”的假象）。
2. **一步生成，不预选范围。** 每臂通读整卷（经 `canon/tools/canon_slice.py` 切片），在一步内完成“选范围 + 精读 + 写锚点”：主轴 scene 详写，物流／过场一句带过。范围切分本身是要被对比的判断，不提前抹平。
   - 退化条款：仅当某卷长到一步通读不可靠（中段开始漏情节）时，才加一个**客观分幕目录**（只列 scene 摘要，不做“算不算关系锚”的判断）；两臂仍各自一步精读。
3. **显式锚点（范围留痕）。** 锚点开头显式标注主轴 scene／只读梗概段／为什么这么切，并能回指 `canon/maintext/卷NN.json`。范围决策是一等输出，不进黑箱，方便对比时第一刀就并排比两臂的范围切法。
4. **分别对比 + 生发新想法。** 从新 session 交叉对比两版：先比范围切法，再比同范围处的精读，并排列出三类分歧（事实／范围／读法）。**但对比不止于机械列差异**——两版并置时才浮出的、任何单版都看不出的新读法／新结构／新落点，正是这一步该交付的产物（本轮卷01 的"延后付款的同行"落点，就是从对比／审里长出来的，不是抄任一单稿）。这一步的纪律只有一条：**不给两臂排名（不自评谁优）、不替人拍板**；在这条线之内，尽管把对比当成生成新想法的场，而不仅是差异清单。
   - **合成时别强焊不同轴。** 把多个 scene 串到一条读法/一条轴上时，连接处必须是文本里的证据，不能是你叠加的解释性 gloss；不同 scene 的伤/机制可能落在不同轴（卷02：留盘缠走"独自上路/共同面对"轴、强弱线走"被依靠"轴），别因为它们服务同一主轴就焊成一条。被排除的弱焊也别一删了之——更有生命力的姿态是给旁轴证据**改派功能**（如强弱线不解释留盘缠的伤点，但能**排除**"赫萝因需要生存照顾才被刺痛"的误读），保留边界又不让证据孤岛化。
5. **人审定稿（同样不止于裁决）。** 必须由人拍板的部分：① 裁决并存读法、决定主稿吸收什么、怎么合；② 读法升格为机制候选的判断；③ 准入测试与字段增删的 gate（见 `架构笔记.md` §0，防 intimacy／conflict residue 那类回潮）；④ 机制正文／policy 定稿；⑤ 原文口径冲突时的最终采信。**但终审本身也带新思考**——人在裁决之上同样会生发对比稿、单稿都没到的新想法（这正是"需要品味"的那部分）；定稿是裁决 + 综合，不是机械二选一。

分界线：可自动化的是**事实核对与差异并置**；但对比与人审**都不止于此**——两步都要在并置之上生发新想法，区别只在"拍板／升格／准入／定稿"这类需要品味与负责的动作归人。别把"对比"误读成只产差异清单、把"人审"误读成只做二选一。

单臂生成提示词已脚本化：`python anchors/build_prompt.py -v <卷号> [--arm claude|codex]` 直接吐出填好的提示词（用法见 `PROMPT_锚点生成.md`；提示词正文是单一事实源，踩坑教训随用随补回脚本）。

## 文件要求

- 文件名含卷号和短标题；scene 范围写进正文「范围留痕」、不进文件名，例如 `锚_卷02_烂好人.md`。
- 必须能回指 `canon/maintext/卷NN.json` 的 scene 范围。
- 允许记录疑问、并存读法和弱模式；不允许把单锚直接写成 Policy。
- 若引用原文，保持短摘；主要写观察和解释路径。

## 弱约束

当前不加字段化 frontmatter。每则锚点只需满足：

- 能回指正典范围。
- 分清事实观察、暂时读法、暂存弱模式。
- 暂存弱模式必须标明临时、带条件、非定稿。
- 不要求产出机制候选。
- **推测必须与原文分开标注**（notebook 层硬要求）：写明「原文提到了什么 / 原文没提、我们推测什么」，推测不得伪装成原文结论；架构层的生成机制候选一律标「候选·锚定正典·定稿归人」，且不主张新增字段（§0 gate 归人）。

## 目录布局

- `extract/claude/`、`extract/codex/`、`extract/glm/`：各真模型臂各自的原始锚点。**Claude 臂**走 Claude Code subagent；**外部臂**是真不同模型经 API 直调（`extract/codex/` 是早期 GPT-5.5/Codex 稿；`extract/glm/` 是当前常驻外部臂 **glm-5.2**，经阿里百炼直调，harness＝`extract/run_glm_arm.py`，纯传输不注入读法）。各臂独立、不共享中间结果。**注意：extract 是生成时的草稿落点，不是可直接取用的定稿层**——定稿/可用层在 `notebook/`。
- **常驻管线（Workflow 编排，见 `extract/wf_anchor_volume.workflow.js`）**：一卷一跑，三阶段——① **双臂**：Claude 臂隔离 subagent 通读写稿 ∥ glm-5.2 臂 API 纯传输；② **分别核查+对抗**：每臂各自做事实层核查（含纯脚本回指闸 `extract/check_refs.py`：ERROR=回指不存在的 scene/行；WARN=紧邻引文对不上所指行）＋ 读法对抗反驳；③ **对比总结**：事实层已由②夯实，本步只比两臂不同思考、给置信度与笔记思路，落 `notebook/对比总结_卷NN`。**两臂/核查/对抗在 workflow 里都是各自 fresh 的 subagent，结构上互不可见——隔离由编排强制，不靠自觉**，这是不让"同源伪交叉验证"发生的护栏。把"忠不忠实"(②，可脚本/agent 自动)与"好不好"(裁决/升格/准入/定稿，归人、不进 workflow)彻底解耦；②只查忠实，**绝不把"像不像原文"当目标**（教训3）。外部臂 API key 从 `DASHSCOPE_API_KEY` 或 gitignore 的 `extract/.dashscope_key` 读，不入库。
- `extract/对比/`：跨臂对比稿的归档。对比稿是生成过程材料、不是定稿层，故归 extract（extract 即草稿/过程层）。卷03 走的是 workflow 常驻管线之前的手工双臂流程，其对比稿移来此处，使 `notebook/` 只留定稿可用层（锚＋atom）。常驻管线（卷06 起）产出的「对比总结_卷NN」暂仍按 workflow 落 `notebook/`，待各卷回填定稿后可一并归此。
- `notebook/`：跨臂对比/合并（已审）后的产物，是实际可用层。卷03 仍保留这套双臂流程之前的早期单窗口/合并稿作对照；卷01、卷02 旧单窗口稿已被新架构吸收并删除。**删除规则：旧单窗口稿只在其新层「终审定稿」后才删（删了对照仍在 git 历史里）——故卷01、卷02 已终审定稿故已删、卷03 未回填故留。**
- **卷05 起试行「架构入口 + 主题原子」分层**（解决单文件过长、细节无处补的问题）；**卷01、卷02 已回填采用同范式**（架构入口 `锚_卷NN.md` + `atom/卷NN_*`，重新吸收旧单窗口稿）：
  - `notebook/锚_卷NN.md` ＝**顶层架构/综合层**：把各主题**串成结论**——这主题说明什么、怎么与别的主题关联、得到什么结论、可如何解读，以及**对最终生成机制的候选分析**（候选·锚定正典·带触发条件与反例，定稿归人，见教训5）。不是罗列、不抄逐场事实。
  - `notebook/atom/卷NN_主题.md` ＝**主题原子**（允许跨 scene）：一个主题一则，短情节 + 简单分析 + 逐行回指 + 横向链接 + 回链架构。另允许第二形态 `notebook/atom/卷NN_微_*.md`：聚焦一处短交互的细读。
  - 后续补细节往原子加，架构入口保持稳定。
