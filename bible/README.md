# 机制工作区（锚点记录先行）

`bible/` 现在不是一组可直接进 system prompt 的成品文件，而是从正典锚点走向机制定稿的工作区。当前原则：

> 先写逐场锚点记录，保留复数读法；等锚点足够厚，再做跨锚候选综合；最后才把被人定稿、且能赢过 bare 的机制结晶进 prompt 文件。

因此，旧 `lore.md` 这类“先给设定/根”的文件已过期，已移入 `archive/`，不得再作为 active 圣经或 bare/base 输入。

## 当前目录

| 路径 | 状态 | 职责 |
|---|---|---|
| `anchors/` | active | 逐场锚点日记。只记录可回到正典的事实、细节、疑问和并存读法；不收敛成机制。 |
| `policy.md` | pending | 人定稿的 Policy 入口。当前仍为空模板；只有跨锚复现、经探针证伪、且过 bare-diff 的机制才能写入。 |
| `archive/` | deprecated | 旧 lore / 旧抽象草稿 / 过早 synthesis。只保留历史脉络，不作为 active 依据。 |

暂不创建 active `lore.md` / `voice.md` / `synthesis/`。Lore、Policy、Voice 仍是最终圣经三层，但它们现在是后验产物，不是起点；跨锚综合也先不占 active 位置，等锚点足够多时再从 `archive/synthesis/` 取回旧候选重审，或新建 active synthesis。

## 流程

### 1. 锚点记录

每则锚点以一段正典切片为单位，写成田野笔记，而不是机制卡。建议结构：

- 本段之前已经在场的东西：前史、关系位置、场面语境。
- 这几幕直接发生了什么：可回到原文的事实观察。
- 值得盯住的细节：指出现象，往下想一层，但停在疑问处。
- 暂时并存的读法：多种能同时成立的解释，互不裁决。
- 现在不要急着抽象成什么：列出诱人的规则，并说明为什么现在太早。
- 可暂存的弱模式：可选，必须标明临时、带条件、非定稿。

关键要求：保留厚度，不把角色坍缩成标签；如果用了“善良”“骄傲”“嘴硬”这类词，要立刻展开它在本场到底如何运作。

当前只加弱约束，不加字段化 frontmatter：锚点必须能回指正典范围，必须分清事实观察 / 读法 / 暂存弱模式，暂存弱模式必须标明临时、带条件、非定稿；不要求每则锚点产出机制候选。

### 2. 候选综合（未来阶段）

只有跨多个锚点复现的解释线，才进入 active synthesis。综合文件应写清：

- 覆盖了哪些锚点，哪些正典位置尚未比对。
- 哪些读法仍并存，哪些已经被跨锚压窄。
- 候选机制的最小生成过程：从场景读出什么，经哪条根或姿态约束，推出什么目的/手段。
- 支持场景与复杂化反例。
- 需要的最小翻转探针对或 round3 覆盖点。

Synthesis 是候选层，不是圣经层。候选可以被推翻、拆分或退回锚点重读。当前早期候选已退到 `archive/synthesis/`，后续到了跨锚综合阶段才能拿出来重挂、重审。

### 3. 定稿结晶

写入 `policy.md` 的门槛：

1. 人定稿机制正文。
2. 至少有跨锚支撑，不是单场景直抽。
3. 能写成可迁移的生成过程，不是判例罗列。
4. 标明支持场景和复杂化反例。
5. 能构造或对应最小翻转探针对。
6. 进入 eval 时必须与 bare 同模型同参数对比，证明有增量。

Policy 越薄越好：它是修正项和门控，不是把赫萝写扁的规则全集。

## 纪律

1. 机制正文由人定稿；Claude 只采正典、做结构化追踪、给锚定候选抽象。
2. 正典是机制假设来源，探针是证伪/防过拟合工具；二者分工不同，不互相替代。
3. 不把“像不像原文表层”当优化目标；提取的是生成过程。
4. 任何字段或机制扩展都要过最小翻转探针对。
5. 旧 `archive/` 内容若要复活，必须先重挂到 `anchors/`；等锚点足够厚，再进入跨锚综合。
