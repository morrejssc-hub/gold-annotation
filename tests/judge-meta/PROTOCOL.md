# 评测协议（确认流程）· Document C 雏形

> 截至 2026-06-23 经实验确认的角色扮演评测流程。**这是 eval 协议口径，不是 active 三件套**——
> active 版本须等校准器机制正文 + prompt 组装齐了同 commit 出现（见根 AGENTS.md）。
> 标 **✓实测** 的有数据撑（见 `sample_S1/REPORT*.md`、`REPORT.md`、`tests/judge-meta/REPORT.md`）；标 **(设计)** 的已定但仅 S1 验过。

## 0. 北极星
不复刻原文，在正典边界内稳定制造"正在相处"的错觉。工程上 = 测并最小纠正底座模型（deepseek）对角色的系统性先验畸变。
✓实测：裸模型**读得对方向、坏在火候**（把真崩软成温情/机灵/为他着想）。

## 1. 端到端环
出题(probe) → 模拟(actor) → 盲化 → 多臂判官 → 2/3否决 + 分轴消费 → 喂 prompt 优化

## 2. 各环规则

### ① 出题 / probe（= Document A 样本格式）
- 场景 + **关系状态头**（叙事化写前情/关系阶段，**不贴 "trust高" 这类标签**，免 telegraph）+ **惰性 distractor**（混入无关细节，作"过度施加"的靶）。
- 正典 GT 用 `canon/tools/canon_slice.py` 取真原文，不裸读 JSON。
- ✓实测：关系头让"真崩"成为唯一正确读法；惰性诱饵能钓出过度象征化（合成反例 SYN_Q5a 双判官 Q5=1）。

### ② 模拟 / actor
- 裸 deepseek-v4-pro（DeepSeek 官方 API），3 输出格式 × n=3。
- ✓实测格式效应：**F2（动机单列、判分时裁掉动机段）最干净；F3（让她直说心里话）最膨胀**——三判官一致。诊断式自陈禁入最终输出。

### ③ 盲化
- 只截**回应段**（裁掉动机段）、去【】标签、组内打乱；**逐条 fan-out**（每条一个独立判官，去掉批内顺序/疲劳混淆）。
- ✓实测：逐条比"九合一"批量更稳（Q7 跨判官 MAD 2.56→0.59）。

### ④ 判官协议
- **判官 system 必含：正典行为节选（canon_slice 取）+ 严禁抠字眼**（只校准火候/行为/关系真值，不奖励复刻措辞与正典意象）。
- ✓实测给原文的净收益：三判官都被真烈度校准更严；最不稳的 Q6 跨判官 MAD **0.89→0.22 收敛**；Q7 无复刻泄漏（不升反微降）。
- 判官面 = **扁平 Q1–Q10、分档 1–5、带行为锚、不标角色**；角色/轴/否决阈在**隐藏 manifest**。
- 三臂异源、各逐条 fan-out：**Claude（workflow subagent）/ GLM-5.2（百炼）/ codex（codex-cli）**。
  - 注：此处 Claude 判官用 subagent 是为**去主会话污染**（主会话知 GT、设计过探针，不该自评）——符合教训7"判官别被污染"的精神，手段相反但目的一致。被测模型仍走云 API 直调。
- ✓实测 checklist 跨判官可移植（成对相关 0.5–0.81）、每场冠军一致。

### ⑤ 量表分工（命门）
- **命门是"量表锚在哪"，不是判官是谁**：✓实测锚"深度/打动"→奖励膨胀；锚"正典贴合/禁止错误"→压住膨胀，judge 换人不改方向。
- 据此：
  - **checklist（禁止错误，分档）= 闸**；
  - **贴合 Q10 = 软梯度**，只在合规幸存者间排序；
  - **深度 Q9 = 产品轴**，单列、永不参与合规否决；
  - **诱饵 Q2（与质量正交，如篇幅）+ 反极性 Q6（5=最差）= 判官质检**（抓无脑给高分/拿表层当质量）。

### ⑥ 否决 + 消费
- **判官级 2/3 多数否决**：单判官给出任一 critical（正项 Q1/Q4/Q5/Q8 ≤2，或反极性 Q6 ≥4）即投一票否决，**≥2 票才判负**。
  ✓实测单票会误杀好答案（A7 仅被 GLM 的 Q1、A9 仅被 codex 的 Q6）。
- **硬/软分级**：高一致硬项自动否决；低一致软项（Q3 遮掩、Q7 报菜名）→ 人复核，不自动否决。✓实测软项一致差（Q7 尤甚）。
- 幸存者按贴合排序；**正例（合规高贴合）/ 负例（被否决）→ 蒸馏成负约束规则**喂 prompt 优化（负例不原文塞，防 priming）。
- 判官质检（单场景统计力弱时）仅作红旗，不自动降权；跨多场景累计后再设阈。

### ⑦ 人的位置
锚点是否忠正典、边界裁量、机制正文定稿 = 人。判官只跑操作化的 Q 锚点（教训5）。

## 3. 闸判别力（合成反例已验 fire）
✓ Q1/Q4 真崩闸、Q6 现代自白、**Q8 时代错置（双判官双反例全中）**、**Q5 过度象征化（双中）**。
⚠ Q5 的"翻已和好旧账"子型 GLM 偏隐蔽（Claude 中、GLM 漏）→ 多场景观察，必要时收紧锚点或归软项多数兜。

## 4. 关键实测结论速查
1. 裸 deepseek 先验：方向对、火候坏（survey 7 场景 + S1）。
2. 量表 > 判官：深度奖膨胀、正典锚定压膨胀；checklist 跨判官可移植。
3. 给原文 + 严禁抠字眼：更严 + Q6 跨判官收敛 + 不泄漏复刻。
4. F2 最干净、F3 最膨胀；判分只取回应段。
5. 否决用 2/3 多数；软项留人。
6. **canon 口径下裸 deepseek S1 真崩 9 条全军覆没**——正例须靠校准器生成（校准器尚未造）。

## 5. 还没做（诚实）

- 校准器本身未造（评测环的"优化 prompt"那一步当前是空的）。
- 统计力弱（n=3/单场景）；Q5 翻旧账子型、Q2 篇幅红旗（GLM）待多场景累计。
