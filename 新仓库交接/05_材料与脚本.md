# 05 · 材料与脚本

## 模型调用方式（前项目实测可用，省得你重查）

### actor / 判官 = DeepSeek 官方 API（OpenAI 兼容）
- base_url `https://api.deepseek.com`，endpoint `/chat/completions`，model `deepseek-v4-pro`。
- 返回带 `reasoning_content`（reasoning 模型）；**max_tokens 要给足**，否则 reasoning 吃光、content 空。
- 纯 urllib 即可（无需 openai 包）。见 `脚本骨架/gen_actor.py`。

### 判官 = GLM-5.2（阿里百炼，OpenAI 兼容）★ 当前唯一"干净 API 判官"
- base_url `https://dashscope.aliyuncs.com/compatible-mode/v1`，endpoint `/chat/completions`，model `glm-5.2`。
- 同样 reasoning 模型、max_tokens 给足（判 9 段一次给 6000–8000）。
- key 走环境变量或 gitignored 文件，**绝不入库**。

### 判官 = codex（codex-cli，OpenAI/ChatGPT）
- 非交互：`codex exec [--output-schema schema.json] [-o out.txt] [-s read-only] [--skip-git-repo-check] [-C dir] -`，prompt 走 stdin。
- ★ **注意污染**：`-C <repo> -s read-only` 给了它**仓库只读权限**，理论上能读到 GT 文件；prompt 里要明令"别读文件/别用工具"，且**判官该盲**（见 `04`）。要可复现就 **pin 模型**（默认未 pin）、记 prompt。当前缺 OpenAI API key，codex 只能走 CLI，算"过渡臂"。

### 判官 = Claude（前项目用 workflow 逐条 fan-out 的 subagent）
- 纯打分、内联喂、不调工具时污染很小（见 `02` B5）；但要"干净 API 判官"需 Anthropic key（前环境没有）。
- fan-out 模式见 `脚本骨架/workflow_fanout.example.js`：每段一个 agent、schema 强约束输出。

> **判官选型小结**：有 dashscope key → GLM 是现成干净 API 判官。要多臂异源、要 Anthropic/OpenAI API 判官，需补对应 key；否则 Claude-subagent / codex-cli 作过渡臂、标降级。

## 复用要点
- **结构化输出**：所有判官都用 Q1..Qn 的 JSON schema 强约束（`脚本骨架/q_schema.json`）。GLM/codex 偶尔多包一层 `{"A1":{...}}`，解析要兜（见骨架里的 unwrap）。
- **盲化**：`脚本骨架/clip_blind.py`——裁回应段、去【】标签、组内打乱、出 keymap。
- **逐条 fan-out** 优于"九合一"批量（去顺序/疲劳混淆）。
- **预算**：fit 迭代用 1–2 臂，holdout 定稿才上多臂。

## 脚本骨架（`脚本骨架/`，参数化(小说,角色)，拿去改）
| 文件 | 作用 |
|---|---|
| `gen_actor.py` | 通用 actor 生成：(model, system, 用户场景) → 多次采样落 jsonl。含 deepseek/dashscope 两种 base_url |
| `clip_blind.py` | 裁回应段 + 去标签 + 打乱 → 盲评池 + 隐藏 keymap |
| `judge_fanout.py` | 通用判官逐条 fan-out：(judge_system, head, items, schema) → 每段 Q 分。含 GLM 调用 + codex-cli 调用两种 |
| `workflow_fanout.example.js` | Claude workflow 逐条 fan-out 模式（若新 repo 也在 Claude Code 环境内） |
| `q_schema.json` | Q1..Qn 输出 schema 模板 |

## 赫萝难例参照（`参照-赫萝难例/`）
拿来当**格式范例 + 最难验证集**，不是直接复用内容（gate 是真崩/拒收类，换角色要换）。
| 文件 | 是什么 |
|---|---|
| `probes.json` | 7 场景探针库范例（场景/正典GT/禁止错误 checklist 的写法） |
| `sample_S1_sim_prompt.md` | 一个完整 probe 的 actor prompt（关系头+惰性诱饵的写法） |
| `sample_S1_eval_prompt.md` | 配套判官面（Q1–Q10 分档锚点的写法） |
| `sample_S1_manifest.json` | 隐藏映射（角色/轴/否决阈/消费逻辑的写法） |
| `sample_S1_CONCLUSION.md` | 逐条具体结论（怎么把结果讲成不抽象的样子） |
| `sample_S1_REPORT_canon_ablation.md` | "给原文"消融的三判官结果（B3 的证据） |
| `sample_S1_GATE_AND_RULES.md` | 2/3 多数否决 + Q5/Q8 合成反例验闸 |

> 这些是**难角色**的样本：真崩烈度裸模型整批够不到、prompt 大概率修不动 → 新 repo 里用它验"管线在硬角色上是否诚实报硬区"。
