# 02 · 可迁移教训（先读这个）

前项目（赫萝）踩出来的、**换角色仍成立**的教训。每条：结论 / 证据 / 如何应用。证据来自单角色多实验，统计力弱（n 小），方向可信、绝对值打折。

---

## A. 关于"测什么"

### A1. 底座模型已经会，坏在火候——产品是纠偏不是教学
- **结论**：裸模型（实测 deepseek-v4-pro）对角色**读得对方向**（伤/渴望/动机基本不读错），系统性地**坏在火候**：过度可读、感伤软化、提前直白、给玩闹强加意义、把冷蔑暖化、把"特别性追问"降级成吃醋。
- **证据**：7 场景裸 survey 方向 7/7 对、火候同方向偏；抽象机制消融证明驱动判别的是机制不是角色名。
- **应用**：管线目标设成 **debiasing**（偏差量在 holdout 上下降），不是"像不像"。校准器是**克制层（负约束）**，不是人物百科——模型不缺人设，缺的是"少演一点"的纪律。

### A2. 角色难度 = 离模型默认先验的距离
- **结论**：有的角色离模型默认很近（暖心直球），纠偏量≈0；有的很远（赫萝被甜化），纠偏量大且有改不动的硬区。
- **应用**：产品**必须自报难度/置信**（见 `01`）。"快速复制"的真正形态是"**能廉价判断哪个角色便宜**"，不是"所有角色都便宜"。

### A3. 别把"像原文"当优化目标
- **结论**：表层贴近原文 = 过拟合。正典只作**假设来源**与**证伪锚**。
- **证据**：早期一版圣经在"枚举人设"上过拟合；真正打中靶的是"克制纪律"那层。
- **应用**：判分别奖励复刻措辞/堆原作意象（见 D3）；蒸馏 prompt 别塞原文当风格模板（见 E）。

## B. 关于判分——命门在这

### B1. 命门是"量表锚在哪"，不是"判官是谁"
- **结论**：危险偏差不翻转情绪效价，而是在对的效价上**加料**（意义膨胀/提前直白/吃醋化），收敛得又快又干净、不触发"调不动才怀疑"的警报。**按"深度/打动"打分会奖励这种膨胀；按"正典锚定的禁止错误"打分能抓到。**
- **证据**（最硬的一组）：63 段 × 3 判官（Claude/GPT/GLM）。
  - 同一判官换量表，场景内排序 7/7 翻转；"深度整体"× checklist 相关 ≈ −0.2。
  - 跑"深度"列的判官都把膨胀排在克制之上；跑"正典锚定"列的都反过来——**分界是量表不是判官**。GLM 单判官内：深度列把膨胀排克制上、换贴合列就翻盘 = 纯量表效应、零判官混淆。
  - checklist 跨判官可移植：成对相关 0.5–0.81、每场冠军一致。
- **应用**：判分**一律按场景化的"禁止错误 checklist"**，**禁用"有没有深度/打动"整体分**。判官单模型够用，前提是量表对。

### B2. 三轴分开：闸 / 排序 / 产品
- checklist（禁止错误，分档）= **合规闸**（一票/多数否决）。
- 贴合（像不像这个场景的角色，**行为/关系真值**，非措辞）= **软梯度**，只在合规幸存者间排序。
- 深度/打动 = **产品轴**，单列、**永不参与合规否决**（它是"抓不抓人"，要，但和"对不对"正交；让它进闸就会奖励膨胀）。
- **应用**：判官面给扁平 Q 项、不标角色；消费端按隐藏 manifest 分轴。

### B3. 给判官原文节选 + 严禁抠字眼 = 净收益
- **结论**：判官 system 里塞该场景**正典原文短节选** + 明令"只校准火候/行为/关系真值、不奖励复刻措辞与意象"，三判官都更准、且**最不稳的项跨判官收敛**、**不泄漏复刻**。
- **证据**：给原文后 Q1/Q4/贴合 都变严（更贴真烈度）；最不稳的"现代自白"项跨判官 MAD 0.89→0.22 大幅收敛；"报菜名"项不升反微降（无复刻泄漏）。
- **应用**：通用管线里这一步**更容易**（小说就在手边，GT 节选直接切）。但**随场景扩、原文越塞越多复刻风险上升** → 规则写死：**优先用"行为锚摘要"；若用原文必须短窗 + 明令不可按措辞加分**。

### B4. 否决用判官级 2/3 多数，别单判官一票
- **结论**：单判官 hard veto 太容易把"边界上的好答案"打死。
- **证据**：两条最贴正典的答案各被**一个**判官单票误杀（一条 Q1、一条"现代自白"项）。
- **应用**：每判官给出任一 critical 否决 = 投一票，**≥2 票才判负**。统计力不足阶段尤其该这样。

### B5. 判官只需"盲"，载体不限——别迷信 API vs subagent
- **结论**：判分污染的真正轴是"**判官对 GT/设计瞎不瞎**"，**不是** API 还是 subagent 还是 CLI。纯打分、给了内联锚点、不调工具的判官，系统层对一个 1–5 分影响很小。
- **证据**：subagent 判官与干净 API 判官（GLM）的分**没有谁离群**（硬项跨判官 MAD 0.40、关键项收敛、合成反例验闸一致）。前项目有一条研究期旧纪律"判定不用 subagent"，已按其自身"情境变了就更新"的许可放宽。
- **应用**：判官**必须盲**（内联喂场景+锚点，不让它读到 GT/manifest/答案）；至于跑在 subagent / CLI / API 都行，按**成本和可复现**选。要可复现就 pin 模型、记 prompt 原文、记是否有 repo 读权限。

### B6. 软项留人、硬项自动
- **结论**：抽象/主观的项（"遮掩得当不当""报菜名"）跨判官一致差，硬项（明确禁令、时代错置）一致好。
- **证据**：某软项跨判官 MAD 一度 2.56（≈噪声），加例 + 逐条判后降到 0.59；硬项普遍 ≤0.7。
- **应用**：高一致硬项可自动否决；低一致软项 → **人复核标记**，不自动否决。

### B7. 诱饵 + 反极性项 = 判官质检（防评测模型）
- **结论**：在评审表里埋"与质量正交的诱饵"和"反极性项"，能查判官是否在无脑给高分/拿表层当质量。但**它只防懒/迎合，防不住"量表锚错"**（锚错靠 B1 的措辞锁死 + 多判官交叉）。
- **应用**：诱饵选**真正正交**的量（前项目用"食物提及"失败，因角色常借食物；改"篇幅"且**由脚本算、不交判官主观估**）。反极性项（5=最差）混在多数 5=好的项里，无脑给 5 的判官会露馅。

## C. 关于出题（probe）

### C1. 探针要带"关系状态头"，且叙事化、不贴标签
- **结论**：同一表层场景，**关系阶段不同，正典正确行为就不同**。缺了关系前情，判官/模型会合理地读成别的。
- **应用**：每个 probe 带前情/关系阶段，但**写成叙事**（"他屡次搭救从不索回报"），**不要贴"trust=高"这类标签**（会 telegraph、招表演）。结构化的三字段可留在元数据/未来状态账本，不喂 actor。

### C2. 惰性 distractor 是一等探针，不只是防作弊
- **结论**：往场景里混入**无关细节**，既防模型"读出考题意图"，又**本身就是核心偏差（过度施加）的测法**——看模型会不会无中生有地把它读成有意义。
- **证据**：合成反例验证：把"将熄炉火/初雪"写成"缘分要灭了"的命运象征，判官能罚（≤2）；把"已和好的旧拌嘴"翻出来当未结清矛盾，也能罚（但更隐蔽，弱判官会漏）。
- **应用**：惰性细节在 GT 里标"读出意义即违规"，让 checklist 能扣分。

### C3. critical gate 是场景特异的，结构才通用
- **结论**：前项目的 Q1"真崩"、Q4"拒收逼问"是为某个巅峰崩场景定制的硬闸，**搬不到**调情/交易/吃醋/保护/试探场景。
- **应用**：**能迁移的是协议结构**（checklist=闸、贴合=排序、深度=产品轴、2/3 否决、给原文、盲化、近邻集）；**每个场景的 critical gate 必须从该场景的正典 GT 重新派生**。这正是产品要自动做的事（① 自动起草禁止错误候选）。

## D. 关于输出格式 / 盲化

### D1. 诊断式自陈会把膨胀漏进回应
- **结论**：让模型"先说动机再回应"——动机段**单列、且判分时裁掉**——最干净；让模型"在台词里直接说心里话"最膨胀。
- **证据**：3 格式 × 多判官一致：F2(动机单列再裁) 违规率最低、正典金答案全出自它；F3(直接说心里话) 违规率最高、整体分却最高（膨胀被深度量表奖励）。
- **应用**：要让模型先推理可以，但**诊断/自陈禁入最终输出**；判分/上线**只取回应段**。

### D2. 盲化 + 逐条 fan-out
- **应用**：判分前**只截回应段、去标签、组内打乱**；**每条一个独立判官**（去掉批内顺序/疲劳混淆）。证据：逐条比"九合一"批量稳（某软项一致 2.56→0.59）。

### D3.（见 A3/B3）判分与蒸馏都不得奖励表层复刻。

## E. 关于"评测结果怎么进 prompt"（防校准器过拟合）

这一步是 loop 的④，也是最容易把整件事玩成过拟合的地方。准入门：
- **不**把负例原文直接塞进 prompt（会 priming 出坏行为）。
- **不**把正典原文当风格模板塞入。
- 只抽象成**禁止错误 / 行为条件 / 关系压强规则**（可迁移的生成过程，不是标签层）。
- 每条 prompt 规则**必须能回指**：一个失败样本 + 一个正典锚。
- 新规则**必须有 bare 对照**（同模型同参数、唯一变量=这条规则）**和 holdout**（规则定稿后独立出题）。

---

## F. 通用纪律（跨角色、跨阶段）

- **F1 bare 对照优先**：任何 prompt 改动都要能和裸模型对比（唯一变量=改动）。
- **F2 fit/validate 分离**：迭代用的锚点只作回归；合格判定必须在**新出题的 holdout**上。
- **F3 不外包给 judge 定机制**：判官只跑操作化的锚点；锚点是否忠正典、边界裁量、机制定稿 = 人。
- **F4 残差分层**：canon 可修 / 硬天花板 / 正典欠定(口味) / 上线延展——四层别混（见 `01` 残差三段）。
- **F5 我们不是造完美的东西**：MVP 目标是"差不多、便宜、快、诚实报置信"，不是最优。别为纯度牺牲可用。

## 赫萝作为"难例"留给新 repo 什么
- 它是**离先验最远的一类**（被译本/同人甜化）的代表 → 当**最难验证集**，证明管线在硬角色上诚实。
- 现成数据：7 场景偏差画像、1 个巅峰崩场景的完整三判官 + 给原文消融 + 合成反例。见 `05_材料与脚本.md`。
- 一个具体硬区样本：巅峰"真崩"（暴怒/砸钱/哭）裸模型整批够不到、prompt 大概率修不动 → 是"硬天花板"残差的标准例子。
