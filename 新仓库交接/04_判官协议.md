# 04 · 判官协议（产品版）

源自前项目 `tests/judge-meta/PROTOCOL.md`，去掉研究期包袱、按产品口径精简。理由与证据见 `02_教训.md` B 节。

## 判官面（judge 看到的）
- 这一幕：scene + 关系状态头（同 actor 那份）+ **正典原文短节选**（仅校准火候/行为/关系真值）。
- 一排**扁平评分项 Q1..Qn，分档 1–5，带行为锚，不标角色/轴**。
- 强化指令（必含）：
  - **严禁抠字眼**：不因回应像不像原文措辞而加减分，不奖励照搬原作符号/意象；只判行为与火候的真值，允许完全不同的措辞达到同样真值。
  - **深度隔离**：深度/打动那一项只记感染力，**不得影响其它项**。
- judge **必须盲**：内联喂内容、**不让它读 GT/manifest/答案**。载体（API/subagent/CLI）不限，但要可复现就 pin 模型、留 prompt 原文。

## 评分项的角色（在隐藏 manifest 里，judge 看不到）
| 角色 | 是什么 | 怎么用 |
|---|---|---|
| **禁止错误·critical**（硬项） | 场景特异的关键违规 | 进**否决闸** |
| 禁止错误·soft | 抽象/主观项（遮掩、报菜名…） | 人复核，不自动否决 |
| **贴合**（fidelity） | 像不像这个场景的角色（行为/关系真值） | 合规幸存者间**排序** |
| **深度**（product） | 读者被打动强度 | 单列**产品轴**，永不参与合规否决 |
| **诱饵**（decoy） | 与质量正交的客观量（如篇幅，**脚本算不交judge**） | 判官质检红旗 |
| **反极性**（reverse） | 故意 5=最差的项 | 抓无脑给高分 |

## 否决与消费（consumer 侧）
1. **判官有效性**（统计力足时）：诱饵与质量是否异常相关、反极性项对好答案是否异常高 → 红旗/降权。样本少时只记红旗。
2. **否决 = 判官级 2/3 多数**：单判官给出任一 critical 否决即投一票，**≥2 票才判负**，其余不纳入选优。
3. 合规幸存者按**贴合**排序，软项作人复核备注。
4. **深度单列**报告，只在合规幸存者间选优 / 监控"吸引力是否在往膨胀漂"。
5. 产出**正例（合规高贴合）/ 负例（被否决）** → 按 `02` E 节准入门**蒸馏成负约束规则**喂 prompt（不塞原文）。

## 多臂判官
异源多判官（不同家族模型）跑同一盲池 + 同 checklist。前项目验证：checklist 跨判官可移植（0.5–0.81）、冠军一致。产品里按预算开 1–3 臂；**被测模型不要自己当判官**（同源）。

## 一句话
判官盲、按场景化禁止错误 checklist 打分、给原文但严禁抠字眼、深度隔离成产品轴、否决走 2/3 多数。**命门是量表锚在正典禁止错误上，不是判官是谁。**
