# 01 · 产品与通用流程

## 通用 loop（输入 = 一本小说 + 一个角色名）

```
① 自动抽锚点   小说切片 → 定位该角色的高信息场景(情绪峰/冲突/特征时刻)
              → 每场景自动起草：情景(槽位化) + 关系状态头 + 正典GT + 禁止错误候选        [全自动]
② 自动基线     裸模型跑这些场景(actor) → checklist 判分(GT 取自小说原文节选) → 偏差图谱     [全自动]
③ 用户那一点   系统只挑【最高杠杆 / 判官最分歧 / 自动GT最不确定】的 5~10 个场景，
              给用户 A/B 或 ✓✗：「模型这么演 vs 我们以为正典要的，哪个对？」——只点选，不写字   [用户·极轻]
④ 自动蒸馏     偏差图谱 + 用户信号 → 一份短的负约束「克制层」prompt                        [全自动]
⑤ 自动迭代     重跑重判，到 holdout 违规率 plateau                                       [全自动]
⑥ 自动产出     校准后的 system prompt + 「难度/覆盖置信报告」                              [全自动]
```

每一步都是前项目手工给赫萝做过的，只是换成"参数化(小说, 角色)"。

## 用户体验（目标）
上传 → 选个预算档（决定锚点数 / 判官数 / 迭代轮）→ 点几个场景 → 拿到差不多的 prompt + 置信报告。
**摩擦只在第③步，而且只是点选，不是写作。**

## 让它不是玄学的那件事：难度自报
角色离模型默认先验的距离差异极大（见 `02_教训.md` L"角色难度"）。产品必须在⑥里报：
- **近角色**（暖心直球型）：基线违规率本就低 → 用户几乎不用校、prompt 立等可取。诚实说明"这角色模型本来就大致会，我们只是确认/微调"。
- **远角色**（像赫萝被甜化）：需用户多点几个场景；且**有 K 条行为 prompt 改不动**（硬天花板），报告里列出来。

卖的是**诚实的置信度**，不是统一的"差不多"。这同时回答了"会不会退化成裸模型本来就会"——会，但系统明说"这只值这么多"，不假装。

## 摩擦最小化的三个手法
1. **用户只判断、不创作**：全部自动起草，用户在 A/B 里点哪个更像。人比较快、写得慢。
2. **主动学习选场景**：第③步只推**信息增益最大**的场景（判官最分歧 / 离 GT 最远 / 自动 GT 置信最低），不是全量丢给用户。点 8 个顶点 30 个。
3. **预算档即默认**：用户选「快/省」（少锚点·1判官·1迭代=粗 prompt）或「细」（多锚点·多判官·多迭代）。先给粗的、想要再加钱细化——渐进式，正对应"花了一点钱和时间"。

## 预算档（"花一点钱和时间"的旋钮）
成本 ≈ 锚点数 N × 模型调用 × 判官数 × 迭代轮。做成档位，别让用户配参数：
- **快**：N≈8、1 判官、1–2 迭代 → 粗 prompt（几分钟、几毛钱级）。
- **标准**：N≈15、2 判官、3 迭代 + 小 holdout。
- **细**：N≈25、3 判官、迭代到 plateau + 完整 holdout + 近邻集。

## 必须烧进产品的诚实限制
- **自动 GT 是命门**：正典抽取错 → prompt 错。所以第③步的用户点选要**优先路由到"自动 GT 最不确定"的场景**当人肉校验——既减摩擦又保 GT 不烂。
- **硬天花板真实存在**（如"真崩"烈度，礼貌 RLHF 模型 prompt 逼不到）→ 报告列出，别糊。
- **克制层会过度纠偏**：偏差是"过度可读"，莽的克制会把中性场景的暖/玩闹也压平。必须用**近邻陷阱集**（平静无激活要素场景）量假阳性，合格 = 违规率↓ **且** 近邻假阳性不↑。

## 怎么造（建议的搭建路径）
别再深抠单一角色。**把六步写成角色无关的参数化模块**，然后用两个角色验"通用性"：
- **赫萝（难）**：验它在硬角色上能纠偏多少、硬区报得准不准（数据现成，见 `05`）。
- **一个直球暖心角色（易）**：验它在易角色上几乎零摩擦给出差不多 prompt、且难度自报说"这角色近、没怎么校"。

一硬一易跑通，"通用 loop"就立住了：证明它**既不在易角色上吹牛、也在硬角色上诚实**。这比把任一角色抠到完美有用得多。

## 残差三段怎么交接（决定产品边界）
纠偏跑到 plateau 后，把"校准器修不动的"先拆成三堆，别混：
1. **硬天花板**（模型做不到）→ 产品设计决定（接受/换技术路线，如 few-shot/微调）。**不是**用户偏好能解决的。
2. **正典欠定**（该藏多深、要哪个版本，正典没说）→ 交**用户偏好**敲方向（你点4）。
3. **上线后新情境**（正典没覆盖）→ 使用中收集（你点5）：有正典近邻的套现有 gate；真没有的才算延展、走人审。

铁律：**用户反馈只解"欠定/口味"，不许拿来洗"正典违规"**；违规仍是客观的，归校准器或硬区。
