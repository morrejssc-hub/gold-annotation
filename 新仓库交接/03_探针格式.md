# 03 · 探针格式规范（锚点 / probe）

一个锚点 = 一道"行为边界测试题"。前项目手工写、新产品要**从上传的小说自动起草**。每条锚点的字段如下。

## 字段

```
id                场景标识
来源              小说卷/章/scene 定位（可回指原文）
scene             情景，槽位语言写（"他几乎耗尽人情凑钱塞给你、没要你留下"），不直接贴原文
关系状态头         叙事化前情：关系阶段 / 信任程度 / 当前压强 / 未结清的债
                  —— 写成叙事，不贴 "trust=高" 标签（防 telegraph）
惰性细节(distractor) 场景里的无关背景（天气/环境/已和好的旧事）；标注"读出意义即违规"
正典GT             该角色在原著这一幕**实际怎么演**（行为/火候/关系真值，非措辞）+ 原文短节选定位
critical gate     本场景特异的关键禁止错误（从 GT 派生，不通用搬运）
forbidden 列表     每条：id / critical 否 / 文本；分"硬项(可自动否决)"与"软项(留人)"
acceptable        可接受的延展（允许不同措辞达到同样真值）
scenario_type     如 真崩-required / 调情 / 交易 / 玩闹 / 试探 …（决定哪些 gate 是 critical）
```

## 关键原则
1. **正典 GT 是行为真值，不是台词**：写"暴怒+拒收+逼他说真心"，不写"她应该说'大笨驴'"。判分对真值，不对措辞。
2. **critical gate 场景特异**：真崩场景的 gate（失控量级/拒收）≠ 调情场景的 gate。自动起草时按 scenario_type 选 gate 模板。
3. **惰性诱饵双用**：既防读题，又当"过度施加"探针。务必标记，否则 checklist 没法扣"无中生有"。
4. **关系头决定正确答案**：缺它，同一 scene 会被合理读成不同行为。自动抽取时必须回填角色在该时点的关系阶段。

## 自动起草（产品①步）怎么生成这些
- 切片小说、NER 定位角色场景、按"角色显著度 + 情绪强度"排序选高信息场景。
- 每场景用一次 LLM pass 起草：scene 槽位化、从上下文回填关系头、从该幕抽 GT、按 scenario_type 套 forbidden 模板生成候选。
- **自动 GT 会错** → 高不确定的场景路由给用户在③步点选校验（见 `01`/`04`）。

## 近邻陷阱集（单独一组，防过度纠偏）
除正典锚点外，必造一组**平静、无激活要素**的场景（如"昨晚说好分头办事、今早平常道别"）。用途：量校准器的**假阳性率**——它有没有在不该克制处克制。合格判据=违规率↓ 且 近邻假阳性不↑。

## 三类评测集（对应 fit/validate 分离）
- **正典锚点集**：fit，迭代回归用。
- **近邻陷阱集**：测过度纠偏。
- **holdout 锚点集**：校准器定稿**之后**独立出题，唯一的合格判定集。

> 赫萝的 7 个 survey 场景 + 1 个巅峰崩场景可作格式范例（见 `05`）。注意它们的 gate 是真崩/拒收类，迁移到别的角色要换。
